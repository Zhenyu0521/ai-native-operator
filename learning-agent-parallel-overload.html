多agent并行让我非常内耗甚至拖慢我的效率

多 agent 并行不一定带来效率提升。真正的瓶颈，往往是人要在多个上下文、任务记忆和判断标准之间来回切换。

Category AI-Native 工作方法 Published 2026.08.23 Tags 多 Agent / 人机协同 / 上下文切换

是的，不仅没让我的工作效率提升，反而让我非常内耗。

一个很现实的场景，10点到公司，列出了我要做的abcde5件事儿，过往我会逐一解决，每解决一个在纸上画个对勾，懂的人都懂，这种清空待办list的感觉对一个istj来说有多爽！

但现在有了多个 agent 工具（公司提供的类 Codex 桌面工具、类似飞书的IM工具内嵌 agent 等），我的野心来了，我想一股脑在两个小时内全部解决。于是打开全部 agent，开启多个项目会话，逐一写prompt，满心欢喜地等待我的助理们为我披荆斩棘。但这才是最痛苦的时候，各个小助理逐渐返回答案，一次就让你满意是不可能的，你要在多个工具多个会话中来回切换，反复在多个情景、逻辑和记忆中去做判断，告诉它问题在哪里、如何去迭代，我是个J人，我讨厌无序，我更讨厌任何一个问题掉在地上，所以这时候忙碌的不是“助理”，我仿佛成了 agent 的助理，在不同页面和不同会话间疲于奔命，燃尽脑细胞，在公司限定的token消耗完之前，我的脑细胞先被消耗完啦

这情况，很合理

因为人的“记忆”是有限的，其实大家想想，我们日常解决问题，自己头脑风暴时，靠的是基本的逻辑判断，叠加不断调取历史的记忆，也可以理解为是你之前获取的信息和过往的经验，《实践论》也会告诉我们，人的实践的成功是先有感性的认识，才会沉淀为理性的判断，随后指导现实的行为，你自己手动做和让 agent 做，都是实践，逃不出这个闭环。

而且，你很难让自己的大脑一分为二、为三、甚至为四，让每个部分分别调用不同的记忆来做判断。强如双子座这种天生的矛盾体（我就是双子），也很难四脑互博，这已经不是“内耗”，这叫“撕扯”。当然，agent 确实可以，你通过设置多项目的多会话，可以让每个问题只局限在一个会话的上下文里，但矛盾是，你的大脑才是所有 agent 的“中枢”，最终都需要你来判断它输出的内容是否合理，这意味着你还是要在不同的“记忆”和“情境”下来回切换。

所以我现在逐渐调整了人机协同的方式，把我的工作拆分为，要动脑vs重复执行sop，后者用skill做定时触发即可，前者，强制要求自己同时最多解决两个方向的问题，彻底close后才会去向下一个。从多线作战改为单点聚焦，整体效率依然会提升
